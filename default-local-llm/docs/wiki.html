Default Local LLM Documentation

This page is the canonical source for Default Local LLM terminology used by the HTML documentation and design specifications.

Default Local LLM
Default Local LLM is a Ploinky agent that exposes a bundled CPU-oriented language model through an OpenAI-compatible Chat Completions endpoint. Its startup script owns the local inference-process lifecycle and its JavaScript handler owns request forwarding. The agent supplies a usable local default without depending on the Ploinky llm-runtime integration, but it does not provide model discovery, embeddings, provider routing, or automatic fallback.
AgentServer
AgentServer is the shared Ploinky service started after local inference becomes healthy. It receives Chat Completions requests, invokes the command declared in the agent manifest, forwards successful JSON or streaming output, and maps a non-zero handler exit to a server error. It is the client-facing service boundary; it does not load the model or call llama.cpp directly.
llama-server
llama-server is the llama.cpp OpenAI-compatible inference process launched by startup.sh. It loads the configured GGUF model, listens only on 127.0.0.1, owns inference and Server-Sent Events generation, and exposes the health route used during startup and readiness checks. The surrounding handler forwards requests and responses but does not change llama-server's model semantics or scheduling behavior.
Chat Completions handler
chat-completions.mjs is the AgentServer command handler for OpenAI Chat Completions. It reads one JSON envelope from standard input, validates that request.messages is an array, and posts the complete request to the loopback llama-server endpoint. It returns parsed JSON for buffered calls or copies upstream chunks for streaming calls. It reports invalid input separately from upstream failures and does not retry or normalize responses.
Readiness probe
The readiness probe is healthcheck.sh, invoked by Ploinky according to the manifest's interval, timeout, and failure threshold. It succeeds only when llama-server's loopback /health endpoint returns a successful HTTP status. AgentServer startup follows the same health condition, so client traffic is not intentionally exposed before the model process is responsive; readiness does not guarantee a particular generation latency or output quality.
Model artifact
The model artifact is the GGUF file loaded by llama-server. The container image supplies Qwen2.5-Coder-1.5B-Instruct Q4_K_M at /opt/models/Qwen2.5-Coder-1.5B-Instruct-Q4_K_M.gguf, and LLAMA_MODEL_PATH may select another mounted file. Startup fails before launching any service when the selected file does not exist. Compatibility and behavior of an override remain responsibilities of llama.cpp and the operator.
